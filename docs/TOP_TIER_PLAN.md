## 一、静态分析天花板：CodeQL 数据流/污点分析

### 为什么难
- QL 查询语言要学；数据流分析需要构建数据库（compile 追踪）；慢

### 为什么值得
- **跨函数数据流**：`user_input → eval()` 整条污染链，普通 AST/正则永远发现不了
- GitHub 用它在 30k+ 仓库找 0-day——**业界最强静态分析**

### 顶级实现（不搞简化版）
```
方案：codeql CLI（官方开源）+ 自建 QL 查询库
  - 查询：数据流（DataFlow）/ 污点（TaintTracking）/ 路径（PathGraph）
  - 入库：codeql database create（追踪编译）
  - 对 Python/Rust/Go 全套
  - 查询集：codeql 官方 security-extended + 自写 unified-rx 专有规则
落点：bug_scan 的第三后端（正则 → AST → 数据流）
验证：对 VoxelForge-Nexus 跑污点查询，找 unsafe 数据流
```

## 二、图 RAG 天花板：GraphRAG 社区发现

### 为什么难
- Leiden 社区发现 + 分层摘要 + LLM 生成社区报告——管线重

### 为什么值得
- **全局问答**：RAGFlow 只能答局部；GraphRAG 能答"整个项目的架构演化"这种全局问题
- 微软出品 ★35k，论文有完整算法

### 顶级实现（不搞简化版）
```
方案：本地 GraphRAG 管线（python-graphrag 或自研）
  - 实体/关系抽取（LLM）→ 图构建 → Leiden 社区发现 → 社区摘要（map-reduce）
  - 查询：全局搜索（社区报告）+ 局部搜索（实体邻居）
  - 落点：repo_wiki 的"全局理解"层 + lesson 图谱的社区聚合
验证：对 AI知识库生成社区报告，问"跨文档的技术脉络"
```

## 三、树搜索天花板：完整 LATS（值函数引导）

### 为什么难
- 需要值函数（V(s)）——要么训练，要么 LLM 评分；MCTS 四阶段（选择/扩展/模拟/回溯）全要

### 为什么值得
- 纯 UCB 只平衡探索/利用；**值函数引导**知道"这个分支前景好不好"——ICML'24 实证
- 你的 bug_locate 已有 UCB 骨架，升级是自然路径

### 顶级实现（不搞简化版）
```
方案：LATS 完整四阶段
  - 选择：UCT = Q + c·√(lnN/n)（已有）
  - 扩展：LLM 生成候选动作（工具调用）
  - 模拟：值函数评估（轻量模型 or LLM 评分，抄 AlphaCodium 的测试反馈）
  - 回溯：delta 奖励更新（复用 LSE delta）
  - 值函数：可选蒸馏小模型（见域 2）——本地推理
落点：bug_locate 升级 + 新工具 explore_branch（多轮因果探索）
验证：对真实 traceback 定位实验，对比纯 UCB
```

## 四、自我进化天花板：self-play / AlphaZero 式对抗

### 为什么难
- 自我对弈需要对手/评判；训练循环复杂

### 为什么值得
- AlphaZero 证明：**自我对弈 → 超越人类专家**（围棋/象棋/星际）
- unified-rx 的"对手"= 自己生成的 bug 用例；"评判"= 测试通过率——天然适配

### 顶级实现（不搞简化版）
```
方案：工具选择自我对弈（借鉴 AlphaZero + LSE 结合）
  - 策略网络：选工具/动作（蒸馏小模型）
  - 价值网络：评估状态（测试通过率 → reward）
  - 自我对弈：AI 修 bug vs 生成的变异 bug（tautest 变异测试当对手）
  - 训练：trl GRPO 更新策略（域 2 管线）
落点：bug_locate/修复建议的进化 + lesson 策略层
验证：SWE-bench 子集上胜率曲线
```

## 五、本地智能天花板：蒸馏 + 量化（unsloth + onnxruntime）

### 为什么难
- 需要训练数据 + GPU 时间 + 蒸馏流程（教师→学生→对齐）

### 为什么值得
- **专属小模型**：代码注释语义/错误分类/值函数——比通用模型快 10×、离线、隐私
- distil-whisper 实证：6× 快 / 50% 小 / 1% 误差——蒸馏不损失质量

### 顶级实现（不搞简化版）
```
方案：
  - 教师：DeepSeek-V4/Qwen（API 或本地）
  - 学生：Qwen2.5-1.5B 级 / ModernBERT（★1.7k，BERT 现代化版）
  - 蒸馏：unsloth（70% 内存省）+ LoRA → 全量 → onnxruntime 量化（INT8）
  - 数据：从 unified-rx 历史 scan-log / 教训库自动生成（自举）
  - 三个学生模型：①代码语义嵌入 ②错误分类 ③值函数（LATS 用）
落点：⑦本地智能层 + kb_query + 探索引擎
验证：蒸馏模型 vs 大模型 API 精度对比（目标 >95% 保留）
```

## 七、程序分析天花板：符号执行 / 污点（补上漏掉的）

### 为什么难
- 路径爆炸、约束求解、引擎集成

### 为什么值得
- **发现深度 bug**：除零/越界/未初始化——普通扫描 100% 漏
- 工具：angr（★8k+，Python 符号执行）/ Klee（C/C++）

### 顶级实现（不搞简化版）
```
方案：angr 符号执行（Python 集成最容易）
  - 对目标函数做符号执行：约束求解找崩溃路径
  - 落点：bug_scan 的第四后端（深路径）
  - 与 CodeQL 数据流互补：污点找"链路"，符号执行找"路径"
验证：对 VoxelForge-Nexus 的 unsafe 函数跑符号执行
```

## 八、检索天花板：混合检索（BM25 + 向量 + Rerank）

### 为什么难
- 三路融合调参；索引维护

### 为什么值得
- 单路检索各有盲区：BM25 强关键词、向量强语义、Rerank 精排
- **三路融合 = 检索天花板**（业界 RAG 标配）

### 顶级实现（不搞简化版）
```
方案：
  - BM25：tantivy（★15.7k，Rust）或 SQLite FTS5
  - 向量：BGE-m3（多语言）+ onnxruntime 本地
  - Rerank：bge-reranker 或 BCEmbedding（★1.9k）
  - 融合：RRF（Reciprocal Rank Fusion）——无需调权重
落点：cb_index 全文层 + kb_query + lesson 检索
验证：检索质量评测（MRR@10）
```
