# unified-rx 感知域 v5（本质感知架构：穿透引擎 × 按需启动 × 模块化 × 自训模型）

> 2026-08-12 v5 · 回应（核心方法论定稿）：
> - **本质感知**：不拍照不截图，穿透引擎（ECS/场景数据）直接透析真相
> - **本质 OCR**：像 DeepSeek 那样有引导地"分清哪个是哪个"（视觉单元级），不是逐字扫描
> - **按需启动**：模块化，扫全局/扫单个按需加载，显存只给正在用的
> - **自训模型**：通用模型只是候选，自己训的专精模型更强
> - **模块联系**：分割模型/识别模型单个运行但能互相联系，智能体可调用

## 〇、三层本质（你方法论的核心）

```
第一层：本质感知（眼前透视）——不依赖画面，直接穿透引擎
        引擎内部数据（Bevy ECS/场景图/组件）→ 真相
        模型/MCP 只是通道，"打破引擎环境，接触本质"

第二层：本质理解（视觉单元扫描）——不是逐字 OCR
        DeepSeek-VL 式混合视觉编码器：有引导地分清"哪个是哪个"

第三层：按需启动（显存管理）——不全部常驻
        模块注册表 + 懒加载：扫全局的扫全局、扫单个的扫单个
        显存只给正在用的模块，联系靠模块间组合
```

## 一、本质感知：穿透引擎（眼前透视）

### 原理：引擎内部数据 = 最高保真真相

| 感知方式 | 保真度 | 成本 | 本质性 |
|---|---|---|---|
| 截图 + 视觉模型反推 | ★★ | GPU+模型 | ❌ 间接（像素→推断） |
| 截图 + OCR | ★ | CPU | ❌ 最间接（还会错） |
| **穿透引擎（ECS/场景导出）** | ★★★★★ | **0 显存** | ✅ **直接读真相** |

### 技术支撑（实测）

| 技术 | ★ | 用途 |
|---|---|---|
| **bevy_reflect**（bevy 内置） | - | 反射：实体/组件/字段 → JSON（引擎自省） |
| **bevy scene / DynamicScene** | - | 场景序列化（场景图导出） |
| **world.query / ECS 遍历** | - | 按组件查询（"所有 Collider 实体"） |
| **wgpu**（bevy 底层） | 17.8k | 渲染管线理解（场景→像素的路径） |
| **winit** | 6.1k | 窗口/输入事件（UI 事件真相） |
| **bevy_xpbd/avian**（已用） | - | 物理世界真相（碰撞体/约束） |

### 工具形态（穿透引擎的 MCP 工具）

```
engine_query(root, {组件/条件})  → 实体+组件 JSON（ECS 反射）
  "找出所有 Collider 异常的实体" → 引擎直接回答，不是模型猜

scene_export(root, {范围})       → 场景图 JSON（父子/变换/材质）
  "这个场景的结构" → 直接读 DynamicScene，0 显存

physics_dump(root)               → 刚体/约束/碰撞体状态
  "为什么这个模块悬空" → 读物理世界，不是看截图猜

ui_state_dump(root)              → UI 节点树+布局值（运行时）
  "哪个按钮重叠" → 布局值直接算，0 显存 0 模型
```

**关键：这些是纯函数（读引擎数据），0 显存 0 模型，精准★★★★★——比任何视觉模型都准，
因为就是真相本身。**

## 二、本质理解：视觉单元扫描（DeepSeek 式 OCR）

### 为什么 DeepSeek-VL 的思路对（论文实读 arXiv:2403.05525）

```
混合视觉编码器（hybrid vision encoder）：
  ├─ SigLIP（语义编码器）——知道"这是什么"（按钮/文字/图标）
  └─ SAM ViT（实例细节编码器）——知道"边界在哪"（哪个是哪个）
  1024×1024 高分辨率 + 低计算开销（1.3B/7B 都开源）
```

**这就是"视觉单元扫描"**：不是逐字符 OCR，而是**引导 attention 分清每个视觉单元**（哪个按钮、哪个文本、哪个图标），语义+边界同时知道。

### 对比（为什么传统 OCR 是下策）

| 方式 | 精准 | 细 | 强 | 显存 | 本质性 |
|---|---|---|---|---|---|
| tesseract 逐字 OCR | ★★★ | ★★★ | ★★★ | CPU | ❌ 只认字不认识"这是哪个" |
| PaddleOCR（中文） | ★★★★★ | ★★★★ | ★★★★★ | CPU | ⚠️ 认字强但无"单元"概念 |
| **DeepSeek-VL 式混合编码** | ★★★★ | ★★★★★ | ★★★★★ | ~1.5G(1.3B) | ✅ **视觉单元+语义+边界** |

### 落地

```
P1 常驻：DeepSeek-VL 1.3B INT4（~1.5G）——"分清哪个是哪个"
  - UI 截图 → "按钮A/文本B/图标C"（视觉单元列表，不是字符流）
  - 画面 → "左侧红色方块、上方标题栏"（语义+边界）
P2 自训：用自己的数据微调（专精游戏 UI/3D 画面，比通用更强）
```

## 三、按需启动架构（显存管理核心）

### 原理：不全部常驻，按任务加载

```
常驻（≤2GB 合计）：
  ├─ 嵌入小模型（BGE，~0.5G）——kb_query 用
  └─ 轻量视觉（DeepSeek-VL 1.3B INT4，~1.5G）——理解用

按需（用完即释放）：
  ├─ OmniParser（~4G）——UI 元素级解析，用到才加载
  ├─ SAM2（~1G）——分割，用到才加载
  ├─ faster-whisper（~0.5G）——语音，用到才加载
  └─ 大模型 API（0 显存）——判断/问答，按需调用

扫描粒度：
  ├─ 扫全局（full_scan 模式）——模块逐个加载跑完即放
  └─ 扫单个（单文件/单资产）——只加载该模块
```

### 实现（复用 unified-rx 已有机制）

| 机制 | 已有 | 用途 |
|---|---|---|
| 工具注册表 _TOOLS | ✅ | 模块注册（新增感知工具即插即用） |
| 懒加载 import | ✅ | 模型按需 import（不进内存不占显存） |
| local_intel 降级 | ✅ | 模型缺失优雅降级（不炸） |
| **新增：模块生命周期** | ➕ | `module_load(name)/module_unload(name)`——显存申请/释放 |
| **新增：感知编排** | ➕ | `perceive(任务, {粒度})`——按任务选模块+粒度 |

### 模块联系（你说的"联系"）

```
不是无关的一步步，而是可组合：
  engine_query（本质真相）→ 若需视觉确认 → DeepSeek-VL（视觉单元）
  → 若需判断 → DeepSeek API → 结果回流教训/图

  ui_state_dump（布局真相）→ 异常区域截图 → OmniParser（元素级）→ 报告
  mesh_check（网格真相）→ 破面区域渲染 → SAM2（分割确认）→ 报告

每个模块单一职责（分割的管分割、识别的管识别），
组合由编排层（perceive）负责——智能体一次调用完成"本质+视觉+判断"链路。
```

## 四、自训模型路线（"我自己搞的模型比这个强"——对，专精 > 通用）

### 为什么自训更强
- 通用模型（Qwen3-VL/DeepSeek-VL）是"全才"——**每个领域都不是最强**
- 自训专精模型：**只做一件事（游戏 UI 检测/GLB 分类/网格质量），数据全是你的（自举），
  针对你的 4060 Ti 8GB 量化部署**——精度更高、显存更小、免费离线

### 训练方案（4060 Ti 8GB 实测可行）

| 专精模型 | 架构 | 数据（自举） | 方法 | 显存 | 部署 |
|---|---|---|---|---|---|
| 游戏 UI 视觉单元检测 | DeepSeek-VL 1.3B 微调 | 截图+ui_state_dump 自动标注 | QLoRA（unsloth） | ~4G | INT4 ~1.5G |
| 网格质量分类 | 小 CNN/PointNet | trimesh 分析结果做标签 | 全量 | ~2G | ONNX ~0.2G |
| GLB 资产分类 | 小 ViT | 文件名+目录弱标签 | 全量 | ~2G | ONNX ~0.2G |
| 画面质量打分 | NIMA 小模型 | NIMA 伪标签 | 全量 | ~2G | ONNX ~0.1G |
| 教训-任务匹配 | 小嵌入模型 | lesson_extract 已有数据 | 对比学习 | ~3G | ONNX ~0.3G |

**数据自举闭环（关键——你不需要标注）**：
```
截图 + engine_query（真相） = 自动对齐标注 → 训练 UI 检测
trimesh 分析 = 自动标签 → 训练网格质量
NIMA 伪标签 = 自动标签 → 训练画面质量
教训库 = 已有数据 → 训练匹配
```

### 蒸馏链（教师→学生，Hinton/QLoRA 论文支撑）

```
教师：DeepSeek API / DeepSeek-VL 7B（云端，0 显存）
  ↓ 软标签（截图描述/UI 判断/质量评分）
学生：DeepSeek-VL 1.3B / 小 CNN（4060 Ti 训练）
  ↓ QLoRA（unsloth 70.5k★，4bit，~4G）
部署：GGUF/ONNX → llamafile/local_intel（常驻 ≤1.5G）
```

## 五、最终架构总览（v5 定稿）

```
┌─ 本质感知层（纯函数，0 显存）─────────────────┐
│  engine_query / scene_export / physics_dump  │
│  ui_state_dump / glb_info / mesh_check       │
│  collider_check（穿透引擎读真相）             │
├─ 视觉理解层（本地小模型，常驻 ≤2G）──────────┤
│  DeepSeek-VL 1.3B（视觉单元扫描，混合编码）   │
│  BGE 嵌入（检索）                            │
├─ 按需模块层（用完即释放）────────────────────┤
│  OmniParser（UI 元素）/ SAM2（分割）          │
│  faster-whisper（语音）/ PaddleOCR（中文）    │
├─ 判断层（API 按需，0 显存）──────────────────┤
│  DeepSeek（综合判断/问答/建议）               │
└─ 自训层（4060 Ti 8GB 训练，专精部署）────────┘
   QLoRA 微调 → 蒸馏 → GGUF/ONNX → 常驻替换通用
```

**显存预算：常驻 ~2G + 按需峰值 ~6G（游戏不跑时）——全部在 4060 Ti 8GB 内。**
