# 用户设计偏好（给 MCP / 开发使用）—— 长期默认规则

> 来源：用户 2026-08-17 明确指示。**所有项目（游戏/软件/工具）默认遵守**。
> 本文件位于 unified-rx-mcp（用户默认 "IDEMCP"/"MCP" = `D:\开发\unified-rx-mcp`）。

---

## 1. 系统 vs 具体东西（设计性架构第一原则）

- **系统与具体东西分开，但一起搞**：先有通用系统（如纹理/颜色系统），再用它做具体东西（如模块）。
- 例：模块外观不要"每个模块一个建模文件"——做一个**程序纹理系统**（样式+颜色+亮度参数），按需填参。
- 多语言/多方案同理：用 A 搞并发不代表放弃 B——系统层面并进。

## 2. EXE 放置（微信标准——硬性默认）

- **游戏/软件项目的 exe 永远放在项目文件夹最外面**：打开文件夹**第一眼就看到 exe**，不许藏在深层目录。
- 例外：C++ 项目（编译产物在 target/build 属正常）；纯 AI 工具（Python 无 exe）——但**后续加 exe 时必须放最外面**。
- 交付时根目录（如 `D:\开发`）也放一份 exe 副本。

## 3. 旧的东西隔离（重构/换代时）

- **二进制全删，只留源代码**；源码压缩归档到集中位置（含 .git）。
- **旧文档文件名加 `OLD-` 前缀**（不改内容）。
- 新项目独立目录/独立 git，绝不与旧项目混用。

## 4. 命名与指向

- **"IDEMCP"/"MCP" 默认 = `D:\开发\unified-rx-mcp`**（用户口头简称，无歧义指向）。
- **QODER 默认调用**：QODER 及**所有智能体**（Codex/Claude/Reasonix/任何 AI 编码助手）默认调用 unified-rx-mcp——先看本偏好文档 + skills/ 目录，再干活。
- **常态扫描（写完即挖——不是收尾）**：每完成一个代码单元（函数/模块/提交前）立刻跑 `scan_delta`（增量）/`scan_now`（全量）——不依赖提示词、不等到对话收尾。收尾时再补一轮 vuln_scan 全量。
- **前端 skill 必须用**：UI/前端相关工作时，impeccable（反模式词典）/ taste-skill（审美）/ garden-skills（风格配方）/ gsap-skills（动效）/ react-bits（组件）必须参考应用——下载了就要用上，不许裸写。
- **AAA 质量标准（"以后"= 常态规则）**：所有交付按 AAA 级——视觉质量（光影/层次/对比度/动效）、交互（触控目标 ≥32px/反馈/防误触）、性能（零每帧分配/资源复用）、测试（按键压力/快速连按）——交付前自查 + 严厉批评家循环（不达标迭代）。用户说"以后"→写入本文件（长期规则）。
- 用户重复说过两遍以上的要求 = 必须记住并默认执行（如 exe 位置）。

## 5. 其他

- 用户喜欢**设计性架构**：多文件/多项目时，优先建"管理系统"（颜色系统/纹理系统/索引）而非复制文件。
- 挖漏洞/安全扫描是常态：每次对话收尾默认扫（unified-rx-mcp 的 bug_scan 等工具）。
