# unified-rx 特点提取与重组方案（取其精华，重新组装）

> 2026-08-12 · 核心方法论：技术是抽象的，**特点是具体的**。
> 做法：① 提取每个技术/项目/论文的好特点（强项）② 提取旧代码的好特点
> ③ 把特点重新组合 → 搞一个新的 unified-rx。

---

## 第一部分：特点提取表（每个技术的强项/弱项）

### A. 代码智能类

| 技术 | 好特点（提取） | 弱项（丢弃） |
|---|---|---|
| **codebase-memory** | ①知识图谱（节点+边）②调用图影响分析 ③hub/中心性检测 ④单二进制零依赖 ⑤token 省 10× | 图构建复杂、重；非图查询场景杀鸡用牛刀 |
| **AetherStudio** | ①增量同步（编辑→delta，不全文对比）②FastLineIndex O(log n) ③semantic tokens delta 解码 ④热/温/冷存储 ⑤AiRole::Tool 卡片 ⑥权限 L1-L4 ⑦错误脱敏 | 编辑器太重；纯编辑器功能（渲染/输入）与工具箱无关 |
| **ast-grep** | ①结构搜索（模式=代码）②结构化改写 ③Rust 快 | 只做单文件级，无仓库级语义 |
| **tree-sitter** | ①增量解析 ②66+ 语言 ③错误容忍（坏代码也能解析） | 只给 AST，图/索引要自己建 |
| **ctags** | ①轻量符号表 ②极快 ③通用 | 无类型/调用关系 |
| **pyright** | ①静态类型 ②增量检查 ③类型推断强 | 只 Python；重（node） |
| **LSP 协议** | ①标准统一 ②语言服务即插即用 ③语义丰富（hover/ref/def） | 进程通信开销；需语言服务器 |
| **SCIP** | ①索引互操作标准 ②一次索引多端消费 | 生态未成熟 |

|---|---|---|

## 第二部分：特点重组方案（重新搞一个）

> 原则：每个新组件 = 多个"好特点"融合，丢弃弱项；旧特点作地基。

### 新组件 1：掌握引擎（结构 + 语义）
```
= tree-sitter（增量解析，66语言）
+ codebase-memory 特点①④（知识图谱节点边 + 单二进制）
+ AetherStudio 特点②③（FastLineIndex + semantic delta）
+ 旧特点①⑧（O(1) 分发 + Rust 常驻）
+ 旧 cb_index 变更感知
→ cb_index 升级：tree-sitter 图索引 + 增量解析 + 图查询
→ 新工具 repo_wiki：图 → markdown 结构文档（抄 Qoder 特点①）
→ change_impact：调用图影响分析（codebase-memory 特点②）
```

### 新组件 2：语义管线（IDE 级掌握）
```
= LSP 协议（标准统一）
+ AetherStudio 特点①③（增量同步 + semantic tokens delta）
+ pyright/rust-analyzer（强类型后端）
+ 旧特点②⑥（懒加载 + 日志反馈）
→ cae lsp 三件套接线（0 调用 → 工作流核心）
→ 三步走规则：改前 context → 改后 impact → 引用前 verify
```

### 新组件 3：进化记忆（教训层）
```
= LSE（旧，delta+UCB）——保留骨架
+ mem0 特点①（自动提取）
+ Letta 特点①（三层：核心/工作/存档）
+ cognee 特点①（图谱化：教训↔工具↔文件连边）
+ LightRAG 特点①（双级检索：具体教训/通用原则）
+ BGE 嵌入（中文语义检索）
→ lesson_recall_lse 升级：自动提取 + 分层 + 图谱 + 语义检索
```

### 新组件 4：探索引擎（bug 定位）
```
= 旧 UCB（探索-利用平衡）——保留
+ LATS 特点①（值函数引导）
+ ToT 特点①（思维树多步探索）
+ AlphaCodium 特点①（生成→测试→修正循环）
→ bug_locate 升级：值函数引导的多轮树搜索
```

### 新组件 5：质量规则引擎
```
= 旧 std_check 正则层——保留兜底
+ ruff 特点①（AST 规则）
+ semgrep 特点①（模式即规则，跨语言）
+ gitleaks 特点①（密钥库）
+ pyright 特点①（类型检查）
+ 旧特点⑩（沙盒+上限）
→ std_check 多后端：正则 → AST → 模式 → 类型 → 密钥
→ 新工具 secret_scan（gitleaks 规则）
```

### 新组件 6：存储层（日志/索引/记忆）
```
= AetherStudio 特点④（热/温/冷三层）
+ tantivy 特点①（全文索引）
+ 旧 scan_cache（mtime+LRU）
+ 旧 JSONL（保留兼容）
→ scan-log 三层存储 + 全文查询
→ cb_index 图持久化（SQLite）
```

### 新组件 7：本地智能层（蒸馏/嵌入）
```
= onnxruntime（跨平台推理）
+ BGE/text2vec（中文嵌入）
+ unsloth 蒸馏（可选：代码注释语义小模型）
+ 旧特点⑧（rx-core 常驻模式复用）
→ kb_query（知识库语义检索）
→ lesson 嵌入向量
→ 可选：蒸馏代码语义分类器
```

## 一句话总结

> **技术是抽象的，特点是具体的。** 每个技术取它的好特点（codebase-memory 的图、AetherStudio 的增量、mem0 的自动提取、ruff 的规则引擎、LATS 的值函数），丢掉弱项（重量、平台绑定、单一语言），再和旧代码的十个好特点（O(1) 分发、懒加载、错误隔离、防幻觉、Rust 白名单……）融合——**重新搞一个七组件的新 unified-rx**。旧代码不是屎山，是特点的矿。
