# 总线架构（Bus Architecture）

> 用户概念（2026-08-12）：
> "总线是被调用的，调用里面再有各种耦合。总线只是对于这个工具来说是被调用的那状态，
> 但不会影响工具本身启动的各种扫描。要分得清引导——被调用的东西有一部分是引导线的，
> 包括动态索引什么的，都跟被调用关联。日志直接闯进调用里面，让智能体知道出了什么 bug，
> 包括后续维护。"

## 核心：总线 = 被调用状态

**总线不是一个新的程序，而是一个"状态"**：工具（unified-rx MCP）被 RX 调用时
的入口就叫总线。所有与被调用关联的东西都挂在这条总线上：

```
                    ┌─────────────────────────────┐
   RX 调用 ────────▶│  总线（被调用状态 = MCP 入口） │
                    └──────┬──────────┬──────────┘
                           │          │
              ┌────────────▼───┐  ┌───▼────────────┐
              │ 引导线（guidance）│  │ 动态索引（cb_*） │
              │ capability_manifest│  │ cb_index/status │
              │ lesson_recall      │  │ /scan（被调用时 │
              │ hallucination_guard│  │  自动关联刷新） │
              └──────────────────┘  └────────────────┘
                           │
              ┌────────────▼────────────────────────┐
              │ 日志闯进调用（scan-log 反馈）           │
              │ 调用返回时附带该文件/项目已知问题        │
              │ → 智能体知道出过什么 bug（含后续维护）   │
              └─────────────────────────────────────┘
```

## 关键原则

### 1. 总线不影响工具自启动的扫描
工具的**自启动扫描**（daemon 计划任务里的各循环：全盘/窗口/自扫/影子/缓存/仓库管理）
**独立于总线运行**——它们是"工具本身启动的各种东西"，总线（被调用）只是它们之外的
一个**状态**。被调用时触发耦合（影子扫描/日志反馈），不被调用时它们照常自跑。

### 2. 引导线（被调用的一部分）
总线上挂的**引导性质**工具（AI 对话开始时调用）：
- `capability_manifest`：能力边界（有什么/没有什么）
- `lesson_recall_lse`：教训召回（防复发）
- `hallucination_guard`：事实核查（引用前验证）
- `scan_log`：看历史扫描日志（专项目）

这些是"引导线"——引导 AI 怎么干活，与被调用强关联。

### 3. 动态索引与被调用关联
`cb_index`/`cb_status`/`cb_scan`：**被调用时自动关联**——AI 分析仓库调用它们，
索引状态实时反映代码库（变更感知），结果供后续调用复用（知识共享）。

### 4. 日志闯进调用（核心反馈链路）
**扫描日志直接反馈进调用结果**：当 AI 调用扫描类工具（bug_scan/std_check/locate_edit
等）时，返回结果**附带该文件/项目最近的已知问题**（从 scan-log 读取）——
智能体不用额外查日志就能知道"这文件之前扫出过什么 bug"、修复进展（后续维护）。
实现：`_scan_log_tick` 已自动落盘；新增**调用时回读**（见 server.py 的 known_issues 注入）。

### 5. 各种技术在框架上补上去
用户给的技术（IDE/LSP、Qoder 定位、树搜索 UCB、各种算法）**都挂在总线上**，
链路一致：被调用 → 结果 → 日志 → 反馈。已补：IDE（cae_lsp_query/code_context）、
Qoder（locate_edit）、树搜索（bug_locate UCB）、算法（rx-core Rust 纯函数层）。

## 耦合关系（调用内部）

| 被调用 | 耦合触发 |
|---|---|
| bug_scan/std_check（文件） | 影子扫描记录 → scan-log；缓存命中；**已知问题反馈** |
| locate_edit/code_complete | 索引关联（cb_index 状态）；影子扫描跟随 |
| project_scan/full_scan | 四路并行；全盘排除清单；结果落盘 |
| 任何扫描工具 | `_scan_log_tick` 自动落盘（日志闯进调用的数据源） |

## 自启动扫描（独立于总线，daemon 计划任务）

```
unified-rx-daemon（AtLogOn 登录自启）
├── daemon-self    自扫全家（core+scripts+lse-engine+vendor）
├── daemon-project 活跃项目（UNIFIED_RX_PROJECT / stats 最活跃）
├── daemon-full    全盘扫（排除 Steam/无关目录）
├── daemon-repo    仓库管理（7 仓库 PR 轮询）
├── daemon-shadow  影子扫描（RX 调用哪个文件→跟着扫）
├── daemon-window  按窗口扫（活动窗口项目）
└── daemon-cache   缓存维护
```

这些与总线无关——工具活着就跑；总线只是"被调用"时的入口与反馈。
