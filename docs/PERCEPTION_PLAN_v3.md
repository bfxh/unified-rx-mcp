## 一、模型拆分决策框架（核心方法论）

### 原则
1. **任务拆成步骤链**：一个"感知"拆成多步，每步选载体（纯函数/本地小模型/语言大模型）
2. **确定性任务本地**：OCR、分类、嵌入、检测、数值分析——纯函数或小模型，快且免费
3. **创造性任务走语言大模型**：描述、问答、规划——DeepSeek/其他 API（你已有）
4. **显卡是硬约束**：常驻模型 ≤4B INT4；大模型按需加载不常驻
5. **同一模型拆用途**：Qwen3-VL 可做 UI 理解/截图描述/场景问答——**一个模型多个拆分用途**

### 拆分示例：UI 检测（一个任务拆成 3 步 3 载体）

```
任务：检查游戏截图 UI 有没有问题
├─ 步骤1 纯函数（本地，零依赖）：ui_tree_dump——UI 代码树静态断言（布局越界/文本重叠）
├─ 步骤2 本地小模型（GPU 1.5GB）：Qwen3-VL 2B INT4——截图 OCR+UI 元素识别
├─ 步骤3 语言大模型（API）：DeepSeek——"基于步骤2的结构，判断 UI 可用性/给建议"
└─ 结果回流：教训提取（lesson_extract）+ 入图（graph_index）
```

### 拆分示例：3D 资产校验（全本地）

```
任务：校验 GLB 建模导出质量
├─ 步骤1 纯函数：glb_info——GLB 元数据（顶点/材质/动画/骨架/尺寸单位）
├─ 步骤2 纯函数：mesh_check——网格质量（退化三角/非流形/空洞）
├─ 步骤3 纯函数：collider_check——碰撞体与视觉尺寸匹配
└─ 全程无模型——确定性任务不需要 AI
```

### 拆分示例：3D 场景问答（混合）

```
任务：问"这个场景的模块布局有什么问题"
├─ 步骤1 纯函数：scene_graph——Bevy ECS 场景导出（实体/组件/位置）
├─ 步骤2 本地小模型：Qwen3-VL——多视图渲染 → 视觉描述
├─ 步骤3 语言大模型：DeepSeek——结合步骤1的结构 + 步骤2的视觉，综合判断
└─ 结构信息来自本地（精确），视觉来自本地小模型（实时），推理来自大模型（聪明）
```

## 二、感知能力 × 载体矩阵（完整拆分）

| 感知能力 | 步骤1（确定性→本地） | 步骤2（视觉→本地小模型） | 步骤3（推理→语言大模型） | 显卡占用 |
|---|---|---|---|---|
| **UI 检测** | ui_tree_dump 纯函数 | Qwen3-VL 2B（OCR+UI 识别） | DeepSeek 判断 | ~1.5GB |
| **截图描述** | -（截图就是输入） | Qwen3-VL 2B（描述） | -（模型已够） | ~1.5GB |
| **GLB 校验** | glb_info+mesh_check 纯函数 | - | -（确定性） | **0（纯 CPU）** |
| **碰撞体检查** | collider_check 纯函数 | - | - | **0** |
| **场景问答** | scene_graph 纯函数 | Qwen3-VL 渲染描述 | DeepSeek 综合 | ~1.5GB |
| **语音指令** | - | faster-whisper small（转文字） | DeepSeek 理解指令 | ~0.5GB |
| **物体检测** | - | SAM2 小模型（分割） | -（模型已够） | ~1GB |
| **知识检索** | BM25 纯函数（已有） | BGE 嵌入（本地） | DeepSeek 生成回答 | ~0.5GB |

**关键结论：显卡预算永远 ≤2GB 常驻**（Qwen3-VL 2B + whisper small + 嵌入），
游戏运行（VoxelForge 545MB）不冲突；大模型按需 API 不占显存。

## 三、本地 vs 语言大模型分工（拆分原则）

| 判定 | 本地（纯函数/小模型） | 语言大模型（API/DeepSeek） |
|---|---|---|
| 任务类型 | 确定性/数值/结构/实时 | 创造性/理解/规划/综合 |
| 示例 | OCR、嵌入、检测、GLB 校验、UI 树断言 | 截图判断、场景问答、建议生成 |
| 成本 | 免费、快、隐私 | 按 token 计费 |
| 延迟 | ms 级 | 秒级 |
| 失败模式 | 确定性可测 | 幻觉（需要防幻觉闭环——你已有） |

**混合决策规则**：
- 有精确答案的 → 本地（纯函数 > 小模型）
- 无精确答案需理解 → 大模型
- 本地小模型输出 → 喂大模型综合（**本地给事实，大模型给判断**）

## 四、修订路线（按拆分后的载体分组）

| Phase | 内容 | 载体 | 显卡 |
|---|---|---|---|
| **P0** | glb_info + mesh_check + ui_tree_dump + collider_check | **纯函数** | **0GB（CPU）** |
| **P1** | screenshot_describe + ui_understand | **Qwen3-VL 2B INT4**（本地）+ DeepSeek 可选 | ~1.5GB |
| **P1** | screenshot_ocr | **RapidOCR**（本地，CPU） | 0GB |
| **P2** | scene_qa（scene_graph + Qwen3-VL + DeepSeek 三链） | 混合 | ~1.5GB |
| **P2** | voice_cmd（faster-whisper small → DeepSeek） | 混合 | ~0.5GB |
| **P3** | Rust 原生（burn/candle 蒸馏 Qwen3-VL→小模型） | 本地 Rust | ~1GB |
| **P3** | 多模态检索（kb_query + CLIP/BGE 视觉嵌入） | 本地嵌入 | ~0.5GB |

**P0 是纯函数（显卡 0 占用）→ P1 本地小模型（≤2GB）→ P2 混合（本地+大模型）→ P3 Rust 原生。**
**每一步都考虑你的 4060 Ti 8GB：常驻 ≤2GB，游戏不冲突。**
