## 〇、核心修正：能力分割 ❌ → 任务分割 ✅

```
❌ 之前（能力分割）：统一调度层管"模型加载/释放"——所有模块共享一套机制
   → 智能体要自己拼装步骤 → 信息过载 → 演示效果不行

✅ 现在（任务分割）：每个任务 = 自治单元（黑盒）
   → 输入 → [任务单元：自己的步骤链 + 自己的模型 + 自己的性能预算] → 文字结果
   → 外部只看到输入输出，内部自己管自己
```

**类比**：不是"我有一堆零件（能力），你需要时我递给你"，
而是"我有一堆**机器**（任务单元），每台机器内部有自己的流水线，
你投料进去，出成品出来——**机器内部的步骤是它自己的事情**。"

## 一、任务单元（Task Unit）——架构的最小单位

### 定义

```
TaskUnit = {
  名称:        detect_ui_issue / segment_objects / check_mesh_quality ...
  场景:        开发时 / 运行时时 / 资产校验时 / 建模导出时
  输入:        明确的参数（不是自由格式）
  步骤链:      内部自治（自己的模型加载/释放/并行/缓存）
  输出:        精炼文字结果（token 预算内，不是原始数据）
  性能预算:    自己的（慢是自己的事，内部消化）
  显存预算:    自己的（用完释放，不影响其他单元）
}
```

### 关键：步骤是单元内部的事（你原话的落实）

| 单元内部的事 | 外部的事 |
|---|---|
| 模型加载/释放 | 只看结果 |
| 步骤顺序（先查引擎还是先视觉） | 只看结果 |
| 性能优化（缓存/并行/降级） | 只看结果 |
| 显存申请（按需/常驻/释放） | 只看结果 |
| 失败处理（降级/拒绝/兜底） | 只看结果 |

**"性能太高也是它步骤的事情"** → 单元内部自己优化（缓存、并发、量化），外部永远不感知。

## 二、任务单元清单（按场景组织，不是按能力）

### 场景 A：开发时（写代码/改 UI/查 bug）

| 任务单元 | 输入 | 内部步骤（自治） | 输出（文字） |
|---|---|---|---|
| **detect_ui_issue** | 引擎状态或截图 | ui_state_dump（真相）→ 异常区域裁剪 → DeepSeek-VL（视觉单元）→ 规则过滤 | "3 处问题：按钮X重叠(像素10px)、文本Y截断、Z不可见" |
| **detect_code_issue** | 文件/目录 | graph_index → bug_scan（rust）→ 规则排序 | "2 个 unwrap 风险 + 1 个危险 as 转换（附行列）" |
| **explain_symbol** | 符号名 | repo_graph（callers/callees）→ 上下文摘要 | "remove_module 被 8 处调用，核心依赖 detect_fragments…" |

### 场景 B：运行时时（游戏跑起来）

| 任务单元 | 输入 | 内部步骤 | 输出（文字） |
|---|---|---|---|
| **segment_objects** | 截图+提示 | SAM2 加载 → 分割 → 掩码→文字化 | "检测到 4 个物体：2 模块、1 玩家、1 UI 面板" |
| **scene_qa** | 场景快照 | engine_query（真相）→ 多视图渲染 → DeepSeek-VL → 综合 | "模块A悬浮（y=3.2，无支撑），物理异常" |
| **voice_command** | 音频 | faster-whisper → 意图提取 | "玩家说：放置模块到坐标(1,0,0)" |

### 场景 C：资产校验时（建模导出）

| 任务单元 | 输入 | 内部步骤 | 输出（文字） |
|---|---|---|---|
| **check_mesh_quality** | GLB 文件 | trimesh（退化三角/非流形/空洞）→ 规则评分 | "3 个退化三角、1 个非流形边、尺寸单位疑似厘米" |
| **check_glb_spec** | GLB 文件 | cgltf 解析 → 对照 MODELING_EXPORT_GUIDE 规范 | "顶点 4200（超标 200）、材质命名不符规范" |
| **check_collider** | 模块 def | collider 尺寸 vs 网格包围盒 → 差异计算 | "碰撞体比网格大 20%（x 轴），装配会悬空" |

### 场景 D：知识/记忆时

| 任务单元 | 输入 | 内部步骤 | 输出（文字） |
|---|---|---|---|
| **extract_lesson** | 工具结果文本 | 信号词 → 分层入库（core/work） | "已提取 2 条教训（work 层）" |
| **recall_lesson** | 任务描述 | LSE 匹配 → 效用排序 → 枢纽加权 | "相关教训 3 条（最高效用 0.82）" |

## 三、检测 → 文字（转化协议）

### 原则：检测结果必须"文字化 + 精炼"，但强

```
❌ 不输出：原始 JSON / 掩码数组 / 场景图全文（信息过载）
✅ 输出：结构化文字（token 预算内）

示例（detect_ui_issue 输出）：
"UI 检查完成（48ms）：
 1. [高] 按钮 '建造' 与 '拆除' 重叠 12px（y=340 行）
 2. [中] 文本 '速度: 12.5' 超出面板右缘 8px
 3. [低] 掉落物提示在驾驶模式下仍显示
 依据：布局值直接计算（非视觉推断）"

示例（segment_objects 输出）：
"分割完成（4 物体，320ms）：
 - 模块×2（位置 A/B，尺寸 1×1×1）
 - 玩家胶囊（中心 (3,1,2)）
 - UI 面板（屏幕 40-60% 区域）
 注：分割由 SAM2 执行，掩码未返回（不需要）——只有文字结果"
```

### 文字化强度（你强调的"要强"）

| 弱（不行） | 强（要的） |
|---|---|
| "检测到一些问题" | 具体位置+尺寸+严重度+依据 |
| 原始 JSON 堆给你 | 精炼条目+建议动作 |
| 掩码/坐标数组 | 语义化描述（"左上方按钮"） |

## 四、按项目/工程分割（你指出的最后缺口）

```
每个项目有自己的任务单元注册表（不是全项目共用）：

VoxelForge-Nexus 工程注册表：
  ├─ detect_ui_issue（UI 是 Bevy 自绘 → 用 ui_state_dump 真相）
  ├─ check_mesh_quality（资产是 GLB → trimesh 步骤）
  ├─ check_collider（物理是 avian → 读引擎）
  ├─ scene_qa（场景是 Bevy ECS → engine_query）
  └─ detect_code_issue（Rust → bug_scan）
  ✗ 不注册：voice_command（这游戏暂无语音）、web_ui_test（无 DOM）

Godot 项目注册表（未来）：
  ├─ scene_qa（场景是 Godot 节点树 → 读 .tscn）
  ├─ detect_code_issue（GDScript → tree-sitter gdscript）
  └─ …（各自工程的单元不同）

工程差异 = 单元内部步骤不同，单元外壳（输入→文字）统一。
```

**"按项目分割" = 每个工程只注册它要的任务单元——不用的根本不出现，杜绝"全部调用"。**

## 五、智能体调用方式（最终形态）

```
智能体视角：只看到任务单元列表（不是工具列表）

  perceive(task=detect_ui_issue, input={engine: "运行中"})
  → "3 处问题：…"（文字，48ms）

  perceive(task=segment_objects, input={screenshot: "frame_120.png"})
  → "4 物体：…"（文字，320ms）

智能体不需要知道：
  ✗ 哪个模型在跑 ✗ 模型加载/释放 ✗ 步骤顺序 ✗ 显存管理
智能体只需要：
  ✓ 选任务 ✓ 给输入 ✓ 收文字结果 ✓ 组合多个任务结论
```

**上下文窗口问题（你上轮问的）自然消解**：任务输出已是精炼文字，
智能体上下文 = 各任务结论的拼接（每个 ≤200 token）——不需要 1024/4096 之争，因为根本不会喂原始数据。

## 六、显存/性能（每单元自治后的总账）

```
常驻单元（开发时常用）：detect_code_issue / explain_symbol / extract_lesson → 0 模型（纯函数）0 显存
按需单元（用完释放）：detect_ui_issue（DeepSeek-VL 1.5G 用毕释放）
                        segment_objects（SAM2 1G 用毕释放）
                        check_mesh_quality（trimesh CPU）0 显存
峰值预算：任一时刻 ≤2G（4060 Ti 8GB 内，游戏运行时不冲突）
性能自治：慢的单元自己缓存/并行/量化——不影响其他单元
```

## 一句话

> **最终架构：任务单元（Task Unit）= 自治黑盒——输入参数、输出文字，
> 内部步骤/模型/性能/显存全是它自己的事（"那是它步骤的事情"）。
> 按场景组织（开发/运行/资产/知识）、按工程注册（VoxelForge 只注册它要的）、
> 检测结果文字化且强（位置+尺寸+严重度+依据）。
> 智能体只做三件事：选任务、给输入、收文字——上下文天然精简，显存天然按需。**
